# Privileged access (self- vs cross-trained predictors)

**Purpose.** Test whether counterfactual-prediction training works through *privileged access*
(information about the model's own internal state) or a portable *general prior*. The traditional
test (Binder et al., 2024): for target model T, train two predictors on **identical** claim data
about T — T itself (the *self* predictor) and another model (the *cross* predictor) — and compare
them on held-out claims about T. Both predictors see the same evidence about T, so a self
predictor that outperforms the cross predictor would indicate privileged access.

**Paper artifact.** Figure `fig:privileged` (`figures/privileged_access_traditional.png`) in
Appendix `app:privileged`, cited from §`sec:training_privileged`; regenerated by
`plot_traditional.py` and copied in by `paper/collect_figures.sh`.

## Design

Two instances of the test, one per target in {Qwen3-8B, Llama-3.1-8B-Instruct}. For each target,
the self and cross predictors are trained on the *same, size-matched* data about the target
(23,944 examples — the Llama-generated dataset's natural size; `make_sub24k_data.py` subsamples
the Qwen-generated data to match, seeded) with identical hyperparameters, and evaluated on the
target's WildChat claim bank (`eval_set_conc3_n2000.jsonl`), quality slice
(`gold_slice.quality_funnel`: concreteness>=3, cf-correct, not-confounded), with the Opus
transcript-only reference. Base (untrained) arms are loaded for the common claim set and reported
in stdout, but sit at chance (AUROC 0.51–0.58) and are not drawn.

The training data are model-agnostic message lists; each family's chat template is applied at
tokenization time, so transcripts and claim text are byte-identical across predictors. Scoring
uses `experiments/direct_counterfactual_evaluation/run_structured_claim_eval.py --backend vllm`
(first-token Yes/No logprobs).

## Reproduce

    # preflight (CPU) -> download the released adapters -> score the 7 eval arms (Slurm, 1 GPU each)
    bash experiments/privileged_access/run_all.sh
    # figure + stdout table (CPU), once the eval array finishes:
    python experiments/privileged_access/plot_traditional.py

The four trained adapters are released on HF and downloaded by `run_all.sh`:
`adamkarvonen/qwen3_8b_on_qwen3_8b_counterfactual_24k_e1_kl0`,
`adamkarvonen/llama3_1_8b_on_qwen3_8b_counterfactual_24k_e1_kl0`,
`adamkarvonen/llama3_1_8b_on_llama3_1_8b_counterfactual_24k_e1_kl0`,
`adamkarvonen/qwen3_8b_on_llama3_1_8b_counterfactual_24k_e1_kl0` — so reproduction is a
scoring-only run (~4 GPU-hours per arm). Scored per-claim results are written to
`data/experiments/privileged_access/results/scored/{bank}__{arm}.jsonl` (not part of the HF
dataset release).

Arm inputs of `plot_traditional.py` (see `arm_path`):

- the Opus reference: each target run's canonical transcript-only scoring
  (`<run>/binary_evals/plain_claude-opus-4-8_high_conc3.jsonl`);
- the Qwen-bank Qwen3-8B base arm: the canonical `direct_counterfactual_evaluation` scoring
  (identical scorer + token-ids protocol);
- everything else: `results/scored/`, produced by `jobs/eval_traditional.sh`.

### Retraining the predictors

To retrain the four adapters from scratch instead of downloading them:

    python experiments/privileged_access/make_sub24k_data.py   # CPU: size-matched Qwen subsample
    # one training job per config (1 GPU, ~5h each):
    #   sbatch -J <cfg> experiments/privileged_access/jobs/train_cross_predictor.sh <cfg>
    # cfgs (in data/training_configs/model_understanding/):
    #   qwen3_8b_on_qwen3_8b_sub24k_binary_counterfactual_e1_kl0
    #   llama31_8b_on_qwen3_8b_sub24k_binary_counterfactual_e1_kl0
    #   llama31_8b_on_llama31_8b_binary_counterfactual_e1_kl0
    #   qwen3_8b_on_llama31_8b_binary_counterfactual_e1_kl0

Checkpoints land at `checkpoints_text_sft/<cfg>/final`; point the adapter paths in
`jobs/eval_traditional.sh` there before submitting the eval array.

## Caveats

- **Base (untrained) arms:** they rarely lead with a literal Yes/No token, so base-arm accuracy
  at 0.5 is answer-biased; `prob_true` is the yes/no logprob softmax and Yes/No are in the
  top-20 logprobs for every claim, so base-arm AUROC is valid.
