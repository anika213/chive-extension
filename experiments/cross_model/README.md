# Cross-model predictor replication (Gemma-3-27B claims)

**Purpose.** Re-run the binary-claim eval with **GPT-5.5** and **Gemini-3.1-Pro** (via
OpenRouter) as the predictor agent, across all interp-tool arms, to test whether the paper's
no-uplift result is Opus-specific.

**Paper artifact.** Table `tab:crossmodel` and the analysis in Appendix `app:crossmodel`
(cited from §`sec:interp_eval_results`). `crossmodel_table.tex` is regenerated by `analyze.py` —
copy it into the paper verbatim so the table and `SUMMARY.md` can never drift. All numbers live
in the paper and the auto-generated `SUMMARY.md`.

## Setup

- **Bank:** `data/runs/opus_investigates_gemma3_27b_it_5000_thorough_n30/eval_set_conc3_n2000.jsonl`
  (~1,750 claims).
- **Arms:** `plain`, `nla`, `sae`, `ao` (`cf` skipped — needs a second Gemma GPU target server
  and is the most expensive arm).
- **Answerers:** `openai/gpt-5.5` and `google/gemini-3.1-pro-preview` (OpenRouter) plus
  `claude-opus-4-8` (Anthropic), all at reasoning effort `high`. Opus is **re-run** here on the
  same tool interface as GPT/Gemini so all three are directly comparable (see Caveats).
- **Reported population:** the raw eval runs over the full concreteness set, but `analyze.py`
  restricts to the paper's **final evaluation dataset** — the quality slice
  (concreteness≥3 ∩ cf-correct ∩ not-confounded, 1,380 claims, from `gold_slice.quality_ids`) —
  so the reported numbers match the main figures.

## Reproduce

    # full run (three answerers in parallel, all four arms)
    bash experiments/cross_model/run_all.sh

    # smoke run (NLA only, 20 claims)
    ARMS="nla" MAXCLAIMS=20 bash experiments/cross_model/run_all.sh

Env knobs: `ARMS` (default `plain nla sae ao`), `CONC` (API concurrency per model, default 100),
`AO_CONC` (shared AO-server concurrency per model, default 40), `MAXCLAIMS` (smoke cap, default
full). `plain`/`nla`/`sae` need no GPU (the NLA/SAE reads come from precomputed caches next to
the bank); the `ao` arm submits the Gemma AO server (`chive/binary_eval/agent/jobs/serve_gemma_ao.sh`,
1 GPU) and waits for it.

Per-claim results (with full transcripts): `data/experiments/cross_model/results/` — kept out of
the run dir's canonical `binary_evals/` so the main plotter's claim-id intersection is never
perturbed. `analyze.py` reads that dir, restricts each arm to the claim ids common to all
answerers, and writes `SUMMARY.md` (all numbers) + `crossmodel_table.tex`.

**Backend support.** `run_binary_eval` drives both the plain answerer and the tool-using agent
through the `LLMClient` abstraction, so `--answerer-backend openrouter` works for every arm.
Anthropic prompt-caching breakpoints ride through `AnthropicLLMClient` verbatim; on OpenAI-style
backends they are stripped to plain text and the provider caches automatically.

## Caveats

**Opus provenance.** The canonical Opus numbers in the run dir's `binary_evals/` were produced
with the tools' earlier key-presence selection schema, which GPT-5.5 could not drive (it emits
every property with empty defaults, so every call failed). All three answerers here use the
current single `selection`-string interface (`transcript_segments.parse_selection`). Opus was
re-run on it for this comparison; its results closely match its canonical numbers (no
regression), and this experiment's tables use only the re-run results.
