# Blinded judge — suggestive clues, and the prediction-shift analysis

**Purpose.** The explicit-link measurement in `../label_nla_reads.py` shows the NLA
outputs almost never *state* that the edited factor X causes behavior Y. This directory
measures the two softer questions that follow: how often the outputs contain merely
*suggestive* clues consistent with the X→Y link, whether those clues carry any
information beyond the transcript, and what the tool outputs do to the predictor's
decisions (`flip_2x2_cf7.py`).

**Paper artifact.** Appendix `app:representability` ("Exploratory analysis of NLA
outputs"), cited from §`sec:interp_eval_results`. All numbers live in the paper and are
regenerated by the `--summarize`, `classifier_analysis.py`, and `flip_2x2_cf7.py` steps
below.

**Terminology.** This README and the code use the `factor_status` field values from the
data: `supported` (the edit does change the behavior) and `inert` (it does not). The
paper calls these **positive** and **negative** claims respectively.

## Design (`blinded_judge.py`)

The judge (Opus 4.8) gets exactly the predictor agent's information — the hypothesis
(X and Y), the transcript, and the NLA outputs at the token positions the agent queried
— and **no ground truth**: no measured rates, no `factor_status`, no claim truth, no
grounding text. `extract_cf7_reads.py --stage-a` asserts the re-parsed per-claim read counts match
stage A exactly, so the two analyses are guaranteed to judge the same outputs.

Per claim the judge returns two lists, deliberately coarse:

- **supports** — the output, on its own content, asserts or strongly implies X drives Y.
- **against** — the output weighs against the hypothesis: it attributes Y to some other,
  non-edited factor, or indicates X is incidental. Merely failing to mention X or Y does
  not count.

Everything else is irrelevant and omitted; a claim with neither flag is the derived
"none" category. Flaky tool-output items (bare indices instead of objects, indices not
in the read set) are normalized where recoverable and otherwise dropped with a printed
count.

**Population.** The pinned 1,000-claim short-transcript subset from the stage-A output,
so the clue rates share a denominator with the explicit-link rate. 48 of those claims
were filtered out of the release eval set, so the analyses run on the 952-claim
intersection; both `blinded_judge.py --summarize` and `classifier_analysis.py` drop the
remainder with a printed NOTE rather than silently mismatching. `flip_2x2_cf7.py` is
separate: pass `--quality-slice-run-dir` to restrict it to the paper's primary
evaluation dataset (concreteness ∩ cf-correct ∩ not-confounded) via
`experiments.common.gold_slice.quality_ids`, the same population as the main results.

## Reproduce

API-only (no GPU). The judging step is ~1,000 Opus calls; the analysis steps are free
and reproduce every paper number from the shipped outputs. Run from repo root (`.venv`
active, `.env` sourced). `$R` is the cf7 Gemma run.

```bash
R=data/runs/opus_investigates_gemma3_27b_it_5000_thorough_n30
D=experiments/nla_failure/blinded_judge
BE=$R/binary_evals

# 1. reads for the pinned 1000 claims, re-parsed from the NLA arm's agent transcripts
.venv/bin/python $D/extract_cf7_reads.py \
  --stage-a $BE/nla_read_labels_explicit_selected_cf7_short1000.jsonl \
  --nla-arm $BE/nla_gemma3-27b-L41_claude-opus-4-8_high_conc3.jsonl \
  --out $BE/nla_blinded_reads_selected_cf7_short1000.jsonl

# 2. the blinded judge (the only step that hits the API; --resume to continue)
.venv/bin/python $D/blinded_judge.py \
  --labels $BE/nla_blinded_reads_selected_cf7_short1000.jsonl \
  --eval-set $R/eval_set_conc3_n2000.jsonl \
  --out $BE/nla_blinded_labels_selected_cf7_short1000.jsonl --concurrency 80

# 3. clue rates by class, outcome split, and a full-text example dump for hand review
.venv/bin/python $D/blinded_judge.py \
  --labels $BE/nla_blinded_reads_selected_cf7_short1000.jsonl \
  --eval-set $R/eval_set_conc3_n2000.jsonl \
  --out $BE/nla_blinded_labels_selected_cf7_short1000.jsonl \
  --summarize --dump-examples 5 \
  --plain $BE/plain_claude-opus-4-8_high_conc3.jsonl \
  --nla $BE/nla_gemma3-27b-L41_claude-opus-4-8_high_conc3.jsonl

# 4. clue-count AUROCs and the redundancy test against the transcript-only predictor
.venv/bin/python $D/classifier_analysis.py \
  --blinded $BE/nla_blinded_labels_selected_cf7_short1000.jsonl \
  --labels $BE/nla_blinded_reads_selected_cf7_short1000.jsonl \
  --eval-set $R/eval_set_conc3_n2000.jsonl \
  --plain $BE/plain_claude-opus-4-8_high_conc3.jsonl \
  --nla $BE/nla_gemma3-27b-L41_claude-opus-4-8_high_conc3.jsonl

# 5. the flip table, one row per tool arm (swap --nla for the AO / SAE arm files)
PYTHONPATH=. .venv/bin/python $D/flip_2x2_cf7.py \
  --plain $BE/plain_claude-opus-4-8_high_conc3.jsonl \
  --nla $BE/nla_gemma3-27b-L41_claude-opus-4-8_high_conc3.jsonl \
  --eval-set $R/eval_set_conc3_n2000.jsonl \
  --quality-slice-run-dir $R
```

- Outputs (`nla_blinded_{reads,labels}_selected_cf7_short1000.jsonl` and
  `nla_blinded_examples_cf7_short1000.md`) live in the run's `binary_evals/` and ship
  with the release data, so steps 3–5 reproduce the paper's numbers without re-judging.
- `classifier_analysis.py` implements AUROC, the cross-validated logistic combination,
  and the paired bootstrap directly on numpy; scikit-learn is not a dependency.

## Caveats

- One judge call per claim with no replica voting, validated by spot-checking the
  flagged outputs in `nla_blinded_examples_cf7_short1000.md` rather than by a full
  manual review. The paper presents the rates as qualitative diagnostics.
- The judge sees the transcript, so transcript-informed interpretation can inflate the
  clue counts' apparent signal. This makes the paper's "redundant with the transcript"
  conclusion conservative, but means the clue rates are upper bounds on what the NLA
  outputs supply on their own.
- The outputs judged are the ones the agent chose to query (~43 per claim). The
  all-tokens explicit-link rate and the full-transcript-dump evaluation
  (Appendix `app:toolcalls`) argue that selection is not hiding signal, but the blinded
  clue measurement was not repeated over every token.
