# NLA failure — the "genuine explicit link" measurement

**Purpose.** Measure how often the binary-eval NLA arm's per-token tool output actually
verbalizes the *relationship* a counterfactual claim is about — "editing factor X moves
behavior Y" — rather than just the endpoints (X present, Y present). `label_nla_reads.py`
computes this end to end with a two-stage LLM-judge pipeline, on both the tokens the predictor
agent actually queried and on every token of the transcript.

**Paper artifact.** Appendix `app:representability` ("Tool outputs rarely state that X causes
Y", cited from §`sec:interp_eval_results`). All numbers live in the paper and are regenerated
by the `--summarize` step below.

## Pipeline (`label_nla_reads.py`)

Two stages mirror an earlier manual review (a single-call all-rubric judge was tried first and
abandoned as too noisy):

1. **Stage A `--explicit-only`** — recall-oriented flagging of reads that even *look* like an
   explicit X→Y statement.
2. **Stage B `--verify-links <stageA.jsonl>`** — per-claim focused review of only the flagged
   reads. Each candidate gets one category (genuine / next_word / echo / behavior_description /
   generic_reason / wrong_driver) by majority over `--votes 3` replicas; a claim is genuine iff
   ≥1 read is verified genuine.

A read is *genuine* iff it (1) states the mechanism binding X to Y, (2) is specific to the
edit, and (3) is not readable off the page (the echo test) — see `JUDGE_SYSTEM_VERIFY` in the
script. Three prompt clauses are load-bearing for recall (the FORMAT NOTE about NLA
next-token clauses, the requirement-1 positive examples, and the requirement-3 pivot
carve-out); do not remove them when modifying the prompt.

**Reads-per-call.** `--source selected` (~40 reads/claim) uses one call. `--source all`
(~700 reads/claim) uses `--reads-per-call 50` (transcript repeated per chunk, genuine hits
unioned) so long transcripts aren't truncated.

**Denominator.** The judge has no "consistent-with-ground-truth" rule; instead the reported
rate is restricted to claims where the edit genuinely drives the behavior
(`factor_status == "supported"`, half the eval set), so an asserted mechanism on an inert
factor never enters the number. (The judge is still shown the ground-truth block, as the
manual reviewer was.)

## Reproduce

The judging is API-only (Anthropic batch mode); the only GPU dependency is the precomputed
NLA cache (see below). Run from repo root (`.venv` active, `.env` sourced).
`$R` is the cf7 Gemma run: `data/runs/opus_investigates_gemma3_27b_it_5000_thorough_n30`.

```bash
S=experiments/nla_failure/label_nla_reads.py
BE=$R/binary_evals

# selected + all-tokens, stage A then stage B (batch mode)
for SRC in "selected" "all --reads-per-call 50"; do
  .venv/bin/python $S --binary-evals-dir $BE --eval-set $R/eval_set_conc3_n2000.jsonl --label conc3 \
    --source $SRC --explicit-only --mode batch --n-claims 1000 \
    --out $BE/nla_read_labels_explicit_${SRC%% *}_cf7_short1000.jsonl
  .venv/bin/python $S --binary-evals-dir $BE --eval-set $R/eval_set_conc3_n2000.jsonl \
    --verify-links $BE/nla_read_labels_explicit_${SRC%% *}_cf7_short1000.jsonl --mode batch --votes 3 \
    --out $BE/nla_read_labels_genuine_${SRC%% *}_cf7_short1000.jsonl
done

# every paper number + full genuine reads for hand review
.venv/bin/python $S --summarize \
  --selected-a $BE/nla_read_labels_explicit_selected_cf7_short1000.jsonl \
  --selected-b $BE/nla_read_labels_genuine_selected_cf7_short1000.jsonl \
  --all-a $BE/nla_read_labels_explicit_all_cf7_short1000.jsonl \
  --all-b $BE/nla_read_labels_genuine_all_cf7_short1000.jsonl
```

- Claim set: `--select short` — a 1,000-claim balanced sample of claims whose transcript is
  <1,000 tokens (seed 0, stratified); regenerated deterministically, or pass a pinned id list
  via `--claim-ids-file`.
- Inputs: the run's NLA arm `binary_evals/nla_gemma3-27b-L41_claude-opus-4-8_high_conc3.jsonl`
  and the NLA cache `$R/nla_cache/gemma3-27b-L41.jsonl` (needed for `--select short` token
  counts and for `--source all`). The cache is not shipped; it is regenerated by the NLA-cache
  stage of `experiments/main_counterfactual_eval/run_all.sh` (GPU capture server).
- Outputs (`nla_read_labels_{explicit,genuine}_{selected,all}_cf7_short1000.jsonl`) live in the
  run's `binary_evals/` and ship with the release data, so `--summarize` reproduces the paper's
  numbers without re-judging.

## Caveats

- The judge prompt was developed on the cf5 bank (an earlier-generation claim format, used here
  as the development set) and validated against a manual review of 27 flagged cf5 claims, then
  applied unchanged to cf7 — the release claim format — held out. The manual
  labels are recorded in `nla_explicit_link_classification.md`, shipped in the Gemma run's data
  at `$R/cf5/binary_evals/`; the cf5 eval set is `$R/cf5/eval_set_conc3_n2000.jsonl`. The
  original stage-A flags were produced on the `_simple` cf5 NLA arm variant
  (`nla_gemma3-27b-L41_claude-opus-4-8_high_cf5_n2000_simple.jsonl`).
- The single-pass stage-A flagger has recall jitter of ±1–2 claims between runs; stage B uses
  majority voting (2/3 quorum if a vote replica fails).
- The script's *default* mode is a six-bucket relationship-evidence spectrum classifier
  that the paper does **not** use; the paper numbers come
  from `--explicit-only` + `--verify-links` + `--summarize` as above.
- The resulting rates depend on an LLM judge; the paper presents them as a qualitative
  conclusion, not a precise measurement.
