# CHIVE: Counterfactual Hypothesis Investigation Via Edits

Code and data for **"Would this change your answer? Predicting the Effects of Prompt Edits on LLM Behavior in the Wild"** (Karvonen, Ong, Kantamneni & Marks).

CHIVE is an agentic pipeline that discovers naturally occurring model behaviors with non-obvious causes and explains them with counterfactual prompt edits. The resulting datasets are used for two applications: evaluating activation-based interpretability tools, and training models to explain their own behavior.

## Artifacts

- **Datasets** (investigations, eval datasets, evaluation runs): [`adamkarvonen/chive-data`](https://huggingface.co/datasets/adamkarvonen/chive-data) on HuggingFace. Download locally with `python scripts/download_data.py`.
- **Trained LoRAs and Activation Oracle checkpoints**: on HuggingFace under the [CHIVE collection](https://huggingface.co/collections/adamkarvonen/chive-counterfactual-hypothesis-investigation-via-edits-6a5d6a299186cfaf6a2e9e20). See [`docs/models_and_checkpoints.md`](docs/models_and_checkpoints.md) for the full table of models and what each was used for.

## What are you here for?

- **Replicating paper experiments** → [`experiments/`](experiments/). One directory per paper figure/table, each with a `README.md` (commands and prerequisites) and a `SUMMARY.md` generated by its `analyze.py`.
- **Running the investigation pipeline on your own model** → [`chive/pipeline/README.md`](chive/pipeline/README.md). Sample a target model on real prompts, screen for unexpected behaviors, investigate causes with counterfactual edits, verify.
- **Running the behavior prediction eval** (transcript-only baselines, or agents with AO / NLA / SAE / counterfactual tools) → [`chive/binary_eval/README.md`](chive/binary_eval/README.md).

## Setup

We use [uv](https://docs.astral.sh/uv/) with a committed lockfile:

```bash
uv sync                            # base deps: enough to run every experiments/*/analyze.py on a CPU-only machine
python scripts/download_data.py    # HF dataset repo -> data/
```

The base install covers the whole CPU-only path — every `experiments/*/analyze.py`, the investigation pipeline, and the eval agents. Add `uv sync --extra gpu` for hardware-bound work: vLLM servers, AO capture, NLA/SAE precomputes, and LoRA text SFT. Plain `pip install -e .` also works if you don't use uv.

API keys are read from a `.env` file at the repo root (`ANTHROPIC_API_KEY`, plus `OPENROUTER_API_KEY` / `OPENAI_API_KEY` / `HF_TOKEN` depending on what you run).

Note: the HF dataset contains the investigation datasets and prompt pools, but not the per-experiment eval result files that the `experiments/*/analyze.py` figure scripts read (`data/experiments/`, run-dir `binary_evals/`, tool caches). Each experiment's README documents how to re-run its evals.

## Infrastructure

All model-facing work for the paper ran on a Slurm cluster with H200 GPUs: GPU work (vLLM serving, activation capture, training) runs as batch jobs, and everything else is a CPU-side driver talking to OpenAI-compatible HTTP endpoints and the Anthropic API. Nothing in the driver code assumes Slurm — any vLLM endpoint works — but the job scripts under `jobs/` are cluster-specific. Read [`docs/infra.md`](docs/infra.md) for the execution model before adapting to your setup.

## Layout

- `chive/` — the installable package (reusable infrastructure)
  - `chive/pipeline/` — the investigation pipeline (start at its [`README.md`](chive/pipeline/README.md))
  - `chive/binary_eval/` — the binary causal-claim eval (start at its [`README.md`](chive/binary_eval/README.md))
  - `chive/training/` — text SFT for self-explanation / counterfactual-prediction training (local LoRA + Tinker backends)
  - `chive/hint_datasets/` — generators for the hint-setting evals (sycophancy AITA, MCQ hints)
  - `chive/paths.py` — single source of truth for data locations (`CHIVE_DATA` env override)
- `experiments/` — one directory per paper figure/table (generate + analyze scripts)
- `paper/` — LaTeX source; `paper/collect_figures.sh` pulls the canonical PNGs from `experiments/*/plots/`
- `data/` — gitignored (except `data/training_configs/`); materialized by `scripts/download_data.py`
- `tools/vllm_pool/` — multi-backend vLLM pool + affinity proxy used for the paper's large runs (optional; any single vLLM server works)
- `jobs/` — Slurm job scripts (cluster-specific; adapt to your setup)
- `docs/` — infra/execution model, models/checkpoints table, and the paper's example-investigation pages (served via GitHub Pages)
